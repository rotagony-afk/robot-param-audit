# 机器人仿真实机参数错配诊断器

## 1. 这个 Skill 做三层事

1. **工程静态比对**：同一个物理量（轮半径、轮距、每转计数、控制频率……）在 URDF、参数 YAML、
   launch、源码里往往被写了三、四遍，且互不一致。工具把它们全部读出来、映射到统一参数名，
   给出每处的**文件 + 行号 + 原文**。
2. **模型级验证（不限差速底盘）**：直接读 MJCF / SDF / JSON 模型，或 STL / OBJ 网格，
   用同一套轮系雅可比判断：这条指令在物理上做不做得到（能不能横移）、轮速是否超限、
   附着是否够、力矩是否够、网格反推的质量与惯量是否与模型声明一致、阿克曼内外轮转角是否合理。
3. **仿真对比与参数反推**：把日志里的命令回放给前向仿真（运动学 + 一阶执行器滞后 + 传输延迟 +
   轮速/附着限制），与实测真值对比；再用"真值/里程计"的直接比值和数值灵敏度，
   收敛出应该修正的**轮半径 / 轮距 / 延迟**。

三层的共同点：**每条结论都带证据**，判不了的明确写出来。

### 适用

- 仿真正常、实车走偏 / 转弯角度不对 / 里程计累计误差大
- 换了底盘（阿克曼、麦轮、全向、四轮滑移），想知道"这条指令能不能做"
- 手里有 3D 模型，想确认模型里的质量和惯量与实物是否一致
- 改了参数文件不生效，怀疑被 launch 覆盖或同键重复
- 搬迁自 ROS 1 的配置，单位可能是毫米 / 英寸
- PID 调不出来，需要先分清是参数错、周期抖还是通信延迟

### 不适用

- 需要图像/点云判断的感知问题
- 需要实机标定的绝对精度（工具只告诉你偏了多少，不替你量轮子）
- 直接解 rosbag2 的 CDR 二进制（需先导出 CSV 或文本）
- **接触动力学仿真**：本项目是运动学 + 准静态动力学，不预测振动、跳齿、翻车

## 2. 输入

| 输入 | 必需 | 格式 |
|---|---|---|
| 工程目录 | 二选一 | 含 .urdf/.xacro、.yaml/.yml、*.launch.py/*.launch.xml、.cpp/.hpp/.py |
| 模型文件 | 二选一 | .urdf / .xacro / .xml（MJCF 或 SDF）/ .json（声明式规格） |
| 3D 网格 | 可选 | .stl / .obj，配合 --density 反推质量与惯量 |
| 实测参数 | 可选 | --reality file.json 或 "wheel_radius=0.0508,mass=12" |
| 运行日志 | 可选 | CSV（带表头）或逐行 key=value / ROS 2 控制台文本 |
| 实测真值 | 建议 | 日志中的 truth_x/truth_y/truth_yaw，或 --expect-distance / --expect-yaw |

日志列名自动识别同义词，例如 cmd_lin / v_cmd / cmd_vel_x、odom_lin / odom_v、
cmd_lat / cmd_vel_y、truth_x / gt_x、t / time / stamp。没有时间列会合成时间轴，并在报告里标注
"频率类指标不可信"。

## 3. 标准工作流程

在 Skill 目录下执行（自带可运行 audit.py，无需安装）：

~~~bash
# A. 只做工程静态比对
python scripts/audit.py static --project <工程目录>

# B. 工程 + 运行日志 + 根因收敛（差速底盘最常用）
python scripts/audit.py full --project <工程目录> --log <日志> --out <输出目录>

# C. 任意底盘模型验证（差速/阿克曼/麦轮/全向/滑移都走这一条）
python scripts/audit.py model --model <模型文件> [--log <日志>] [--mesh <网格> --density 1200]
#    可选：--speed 0.3 --yaw-rate 0.4 --lateral 0.2 --used-radius 0.05 --used-track 0.30
#         --reality reality.json --project <工程目录>（同时做工程静态比对）

# D. 起一个本地 Web App（零依赖，浏览器里拖文件、看结论）
python scripts/audit.py app --port 8765
~~~

退出码：0 = 无严重/高级问题；2 = 存在 CRITICAL/HIGH；1 = 输入不可读。

执行后必须做这三件事：

1. 打开 report.md 的「0. 结论摘要」，逐条核对证据行号是否指对；
2. 打开「5. 未验证 / 无法判定的内容」，把这些**不能当成结论**的项原样转述给用户；
3. 需要修改时，只把 patches/ 里的 diff 展示给用户确认，不要替用户判断哪一处是实物真值。

## 4. 输出

| 文件 | 内容 |
|---|---|
| report.md | 结论摘要、输入指纹、S/R/C/M 发现、未验证项、已通过项、复现命令 |
| findings.json | 机器可读：rule、severity、confidence、status、evidence、proposals、metrics |
| trace.jsonl / trace.md | 逐条调试痕迹（阶段、动作、规则、读过的文件、判定结果） |
| patches/*.patch | 按"文件→行→列"定位的 unified diff（默认不落盘） |

## 5. 规则编号

| 编号 | 检查内容 |
|---|---|
| S01 | 同一参数多处定义且数值不一致 |
| S02 | 疑似单位不一致（10/100/1000/2.54/25.4 倍） |
| S03 | 表达式参数（xacro/launch 变量）未求值，已排除出数值比对 |
| S04 | 轮距声明值与 URDF 轮子 joint origin 几何不一致 |
| S05 | 驱动轮 joint 旋转轴方向不一致 |
| S06 | 质量为 0/负、惯量全 0、连杆缺 inertial |
| S07 | 控制频率高于仿真插件更新频率 |
| S08 | 限速超过轮子实际可达速度 |
| S09 | launch 传入了配置里不存在的数值参数 |
| S10 | 同一 YAML 作用域内重复定义同一键 |
| M01 | 模型参数不完整（无轮子、轮半径为 0、质量为 0） |
| M02 | 该底盘物理上做不出这条指令（残留侧滑 / 转向角超限） |
| M03 | 轮速超限 |
| M04 | 附着不足（需求牵引力 > μ·N） |
| M05 | 力矩不足（超出电机扭矩-转速曲线） |
| M06 | 阿克曼几何缺轴距/轮距，或小半径下内外轮角差异常 |
| M07 | 网格反推的质量/惯量与模型声明不符、网格不封闭、轮子超出包围盒 |
| M08 | 实测参数（轮半径/质量/摩擦）与模型值不一致 |
| M09 | 仿真与实测是否一致 |
| M10 | 根因收敛：应修改的参数与数值（含直接比值与灵敏度两条路径） |
| M11 | 转向几何修正：车身原点需要的侧向速度 |
| A01 | 机械臂目标不可达 |
| A02 | 机械臂解接近奇异位形 |
| A03 | 机械臂负载力矩超过关节额定 |
| A04 | 机械臂自由度不足 3 |
| P01 | 螺旋桨声明推力与 kT/转速不符 |
| P02 | 满转扭矩超过电机上限 |
| P03 | 满油门推力不足以悬停 |
| P04 | 桨盘载荷偏高（效率提示） |
| L01 | 激光雷达声明点数与扫描几何不符 |
| L02 | 安装高度/俯仰导致地面盲区过大 |
| L03 | 精度优于量程分辨率（规格矛盾） |
| R01 | 里程计线位移尺度偏差 |
| R02 | 里程计转角尺度偏差 |
| R03 | 控制周期抖动 |
| R04 | 指令到反馈的响应延迟 |
| R05 | 指令限幅 / 饱和 |
| R06 | 超调与振荡 |
| R07 | 有指令但反馈长时间为 0 |
| R08 | 时间轴与数值列的数据质量 |
| C01 | 线尺度根因收敛（R01 + S01/S02/S10） |
| C02 | 转角尺度根因收敛（R02 + S04） |

## 6. 异常处理

| 情况 | 工具行为 | 你应该怎么说 |
|---|---|---|
| 没有日志 | 只跑静态/模型规则，报告标注 R 类未执行 | 说明静态结论的边界 |
| 日志没有真值列 | R01/R02 判 unverifiable，不给偏差百分比 | 明确"缺真值，绝对尺度无法判定" |
| 参数是 xacro 表达式 | 记为 unresolved，不参与数值比对 | 说明需要先 xacro 展开 |
| 模型里没有轮子 | M01 HIGH，后续规则跳过 | 如实说明模型不足以验证 |
| 指令物理上做不到 | M02，并给出残留侧滑量 | 解释"这部分运动不会发生" |
| 反推值与任何静态值都不匹配 | M10 不给单一根因，列出候选 | 要求补实测数据或第二段行程 |
| 多个参数都能解释同一偏差 | M10 判 unverifiable | 解释"数学等价，需要额外信息" |
| 文件解析失败 | 记入 skipped，明确说明未参与结论 | 如实转述，不得跳过不提 |

## 7. 使用限制

- 只读文件，不读实物；不判断轮子真实直径、电机真实转速。
- 无真值时不输出绝对尺度结论（刻意的设计，不是缺陷）。
- 运动学 + 准静态动力学，**不做接触动力学**：不预测振动、跳齿、翻车、轮胎非线性。
- 不解 rosbag2 的 CDR；需先导出 CSV 或文本。
- --apply 只改 proposals 里的字面量，改前生成 .bak；不重构代码、不改构建系统。
- Web App 只绑定 127.0.0.1 + 一次性 token，不联网、不上传任何数据。

## 8. 机械臂 / 螺旋桨 / 激光雷达 与 Simulink 导出

### 机械臂（A 类规则）

JSON 规格里的 `arm.joints`：每行给出 origin.xyz、origin.rpy、axis、limits（度）、effort（N·m）、velocity（度/秒）。
工具做正运动学、几何雅可比、阻尼最小二乘逆解，并给出：

- A01 目标点不可达（末端残差 > 1 mm）；
- A02 解接近奇异位形（可操作度 < 1e-3）；
- A03 指定负载下关节力矩超额定；
- A04 自由度不足 3。

示例：`python scripts/audit.py model --model ../examples/mechanisms/arm6.json --payload 2.0 --target 0.45,0,0.30`
实际结果：A03「负载 2.00 kg 时关节力矩超限（j5_pitch）」。

### 螺旋桨（P 类规则）

`T = kT * omega^2`、`Q = kQ * omega^2`、`P = Q * omega`。检查：

- P01 声明最大推力与 kT/转速算出的值相差 > 10%；
- P02 满转所需扭矩超过电机上限；
- P03 满油门总推力不足以悬停；
- P04 桨盘载荷 > 400 N/m²（效率提示）。

示例：quad_x.json 声明 14 N，按 kT=1.2e-5、9000 rpm 应为 10.66 N → P01（差 24%）。

### 激光雷达（L 类规则）

点数/秒 = 水平视场/角分辨率 × 线数 × 帧率。检查：

- L01 声明点数与几何不符（> 10%）；
- L02 安装高度与俯仰导致地面盲区半径 > 0.4 m；
- L03 精度优于量程分辨率（规格自相矛盾）。

示例：lidar360.json 声明 10 万点/秒，按 360°/0.2°×16 线×10 Hz 应为 28.8 万 → L01；
0.4 m 安装高度、30° 竖直视场 → 盲区半径 1.49 m → L02。

### Simulink 导出

`--simulink <目录>` 会按刚诊断的对象生成一个模型包：

| 文件 | 用途 |
|---|---|
| `build_<name>.m` | 在 MATLAB 里运行它，用 new_system/add_block/add_line/save_system 生成真正的 .slx |
| `<name>.mdl` | 同一模型的文本版本，可尝试直接双击打开 |
| `params.m` | 模型用到的全部数值，含审计建议的修改 |
| `README.txt` | 模型结构、离线自检结果与能力边界 |

轮式底盘是「一阶速度环 + 里程计增益」；机械臂是「每关节二阶伺服 + 限位饱和」；螺旋桨是「转速滞后 + T=kT·ω²」。
生成后会做离线结构自检（模块名唯一、连线无悬空、端口合法）。

**能力边界**：这些是参数级验证模型，不是接触动力学。生成脚本已在 MATLAB R2025b + Simulink 上实测
（build_rsw_arm6 成功生成 .slx，48 模块 / 48 连线）；本项目构建环境无法启动 MATLAB，故自动化只覆盖
生成脚本语法与离线结构自检，运行波形请在自己的 MATLAB 里点 Run 确认。

## 9. 完整示例

### 8.1 差速底盘：静态冲突 + 运行日志 → 唯一根因

工程：examples/demo_robot（故意埋了 9 处缺陷）

~~~bash
python scripts/audit.py full \
  --project ../examples/demo_robot \
  --log ../examples/demo_robot/logs/run_straight.csv --out ../audit-out/demo
~~~

实际结果：S01 轮半径 0.05 与 URDF 0.0508 相差 1.575%；R01 里程计少报 1.6%；
C01 收敛为"轮半径应为 0.0508"，给出 3 处 diff。

### 8.2 模型验证：麦轮能不能横移（把 roller 角写掉会怎样）

~~~bash
python scripts/audit.py model --model ../examples/universal/mecanum_bot.json \
    --lateral 0.2 --speed 0
python scripts/audit.py model --model ../examples/universal/mecanum_no_rollers.json \
    --lateral 0.2 --speed 0
~~~

第一份能横移（四轮以 ±45° 滚子转动）；第二份把 roller 角写成 0，
工具立刻报 M02「该底盘无法完成横向运动（残留侧滑 0.200 m/s）」。

### 8.3 3D 网格：质量对不上

~~~bash
python scripts/audit.py model --model ../examples/universal/mesh_bot.json \
    --mesh ../examples/universal/chassis.stl --density 1200
~~~

实际结果：M07「网格反推质量 7.200 kg 与模型声明 2.400 kg 相差 200.0%」，
并给出"若要让两者一致，密度应当是 300 kg/m³"。

### 8.4 仿真对比与参数反推

~~~bash
python scripts/audit.py model \
    --model ../examples/demo_robot/description/urdf/demo_robot.urdf \
    --log ../examples/demo_robot/logs/run_straight.csv \
    --used-radius 0.05 --out ../audit-out/sim
~~~

实际结果：M09「仿真与实测一致（位移差 0.03%）」，并给出
"按固件轮半径 0.05 m 推出来的里程计是 0.9816 m，实测 0.9793 m，相差 0.23%"，
M10 收敛为"轮半径应为 0.0508 m（当前用 0.05 m 换算）"。

### 8.5 Web App

~~~bash
python scripts/audit.py app --port 8765
~~~

浏览器打开终端打印的地址（带 token），拖入模型 / 日志 / 网格，点"运行诊断"，
右侧直接显示分级结论、证据与可下载的 report.md / findings.json / trace。
