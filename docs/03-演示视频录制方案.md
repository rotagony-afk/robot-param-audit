# 演示视频录制方案

> 视频要求：真实展示核心功能与使用流程，优先实际运行录屏。
> 本方案按 3 分钟设计，所有命令都真的能跑通，所有输出都是真的。

## 0. 已经准备好的东西

仓库里已有一份**由真实运行输出渲染**的演示视频：`docs/demo-video.mp4`（约 64 秒，1280x720）。
它的每一行终端内容都是 `scripts/audit.py` 的真实 stdout（静态比对 / 运行日志 / 麦轮横移 / 3D 网格），
由 `tools/make_demo_video.py` 采集后逐行回放渲染。**它不是屏幕实拍**。

如果比赛要求“屏幕录屏实拍”，请按下面步骤自己录一遍（约 20 分钟可完成）。

## 1. 录制前准备

| 项 | 内容 |
|---|---|
| 录制工具 | Windows：Win+G（Xbox Game Bar）或 OBS Studio；macOS：QuickTime 屏幕录制 |
| 分辨率 | 1920x1080，终端字号调到 16—18 号（1080p 下别太小） |
| 终端编码 | 先执行 `chcp 65001` 与 `$OutputEncoding = [Text.Encoding]::UTF8`，避免中文乱码 |
| 窗口布局 | 左：终端（占 2/3）；右：文件资源管理器打开 `examples/demo_robot` |
| 提前跑一遍 | 确认 4 条命令都能跑通，避免录制时卡顿 |
| 清理 | 删除 `audit-out` 目录，让“从零生成”更真实 |

~~~powershell
cd <仓库根目录>
chcp 65001
$OutputEncoding = [Text.Encoding]::UTF8
$env:PYTHONIOENCODING = "utf-8"
Remove-Item audit-out -Recurse -Force -ErrorAction SilentlyContinue
~~~

## 2. 分镜脚本（约 3 分钟）

### 镜头 1（0:00—0:20）项目名称与用途

- **画面**：终端顶部，慢慢向下滚动 README 的前 20 行。
- **讲解词**：
  “这是机器人仿真实机参数错配诊断器。仿真里能跑、上实车就跑偏，最常见的原因不是算法写错，
   而是同一个轮半径被写在 URDF、参数文件、源码三个地方，而且三个值不一样。
   这个工具就是把这种‘隐性的参数错配’变成有行号证据的排查。”

### 镜头 2（0:20—0:50）展示问题：三个文件，三个值

- **操作**：在资源管理器里依次打开三个文件，滚动到对应行。
- **要展示的行**：
  - `description/config/demo_robot_params.yaml` 第 7 行：`wheel_radius: 0.05`
  - `description/urdf/demo_robot.urdf` 第 38 行：`<cylinder radius="0.0508" length="0.03"/>`
  - `src/diff_drive_controller.cpp` 第 10 行：`constexpr double WHEEL_RADIUS = 0.05;`
- **讲解词**：
  “实物是 2 英寸轮，半径 0.0508 米，URDF 里写对了；但配置和源码都写成了 0.05。
   差 1.6%。这 1.6% 就是‘走 1 米只记 0.98 米’的来源。人工核对要翻十几个文件，还未必对得上。”

### 镜头 3（0:50—1:25）实际运行：静态比对

- **命令**：

~~~powershell
python ros2-sim-hw-mismatch-auditor/scripts/audit.py static --project examples/demo_robot --out audit-out/demo
~~~

- **要展示的输出**（真实结果）：
  统计 `严重 1 | 高 5 | 中 2 | 低 1`，其中
  `[高] S01 驱动轮半径 多处定义且数值不一致（2 组）`，
  首证据指向 `demo_robot_params.yaml:7`。
- **讲解词**：
  “一条命令，几秒钟。它把每个数值都映射到统一的参数名，所以能发现‘看起来名字不同、其实是同一个量’的冲突：
  wheel_radius、cylinder 的 radius、WHEEL_RADIUS 常量，全被归到同一个参数上。
  每条结论都带文件和行号，你可以直接去核。”

### 镜头 4（1:25—2:10）实际运行：加入运行日志，定根因

- **命令**：

~~~powershell
python ros2-sim-hw-mismatch-auditor/scripts/audit.py full --project examples/demo_robot --log examples/demo_robot/logs/run_straight.csv --out audit-out/demo
~~~

- **要展示的输出**（真实结果）：
  `[高] R01 里程计线位移偏差 1.6%（真值 0.995 m / 里程计 0.9793 m）`；
  `[高] C01 根因收敛：驱动轮半径 应为 0.0508（当前 0.05）`；
  以及 3 条“建议: … 0.05 -> 0.0508”。
- **讲解词**：
  “关键在这里：运行日志告诉我们‘偏了多少’，静态文件告诉我们‘有哪几个候选参数’，
   工具把它当成方程来解——0.05 乘以 1.016 正好等于 0.0508，也就是 URDF 里那个值。
   两路证据独立吻合，才敢说根因收敛。如果吻合不上，它会明确写‘无法唯一确定’，不会猜。”

### 镜头 5（2:10—2:40）输出与补丁

- **操作**：打开 `audit-out/demo/report.md`，滚动到「5. 未验证 / 无法判定的内容」；
  再打开 `audit-out/demo/patches/` 里的 patch 文件。
- **讲解词**：
  “报告里单独有一节‘未验证’，把工具不能判断的事情原样列出来；比如没有真值时它不会给偏差百分比。
   修改建议是标准 diff，按行按列定位，默认不写盘；确认后加 --apply 才写回，并自动生成 .bak 备份。”

### 镜头 6（2:40—3:00）收尾

- **操作**：回到终端，展示 `python -m pytest` 的 `91 passed`。
- **讲解词**：
  “91 个自动化测试，其中一项是逐字核对所有证据行号——报告里引用的每一行必须和文件里那一行完全一致。
   还有一个对照工程，参数完全一致时必须零发现，用来防止误报。工具是纯标准库实现，装上 Python 就能跑。”

### 可选补充镜头（若时间允许，每个 15 秒）

- **麦轮能不能横移**：执行 `audit.py model --model examples/universal/mecanum_no_rollers.json --lateral 0.2 --speed 0`，
  展示 `M02 该底盘无法完成横向运动（残留侧滑 0.200 m/s）`；再换成 `mecanum_bot.json` 展示"可行"。
- **3D 网格质量**：执行 `audit.py model --model examples/universal/mesh_bot.json --mesh examples/universal/chassis.stl --density 1200`，
  展示 `M07 网格反推 7.200 kg vs 声明 2.400 kg`。
- **本地 App**：执行 `run-app.cmd`，浏览器里拖入模型与日志，点"运行诊断"。
